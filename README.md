# Bandi

Ранний локальный прототип Telegram-бота для донатов. **Реальные платежи не подключены: деньги не списываются, счета не создаются.** Проект не готов к production. Лицензия пока не выбрана.

## Срез
- После `/start` — приветствие и кнопка «Личный кабинет». Кабинет оформлен по восьми предоставленным экранам: пополнение, донат, закреп, тег, история, справка, закрытие. Дополнительно сохранены профиль, согласие на рейтинг и рейтинг. Навигация редактирует текущее сообщение; повторное нажатие не вызывает ошибку «message is not modified». Команды `/profile`, `/visibility on|off`, `/donate` и `/top` сохранены для совместимости.
- Кнопка «Поддержать» предлагает несколько сумм или ввод произвольной суммы. Она сохраняет намерение в RUB в минимальных единицах (копейках), **не создаёт счёт и не списывает деньги**. В интерфейсе донатов допустимы целые рубли от 100 до 500 000; статус всегда `unavailable`.
- Кнопка рейтинга работает в личном чате и в группе/супергруппе, включая форумные топики: ответ отправляется в тот же чат и топик. Личный кабинет намеренно доступен только в личном чате; по умолчанию согласия на публичный рейтинг нет.
- Данные пользователей и намерения хранятся в SQLite локально. Платные функции, автопубликация и административные команды не реализованы.

## Запуск только после отдельного решения о тестовом боте
Python 3.11+, установщик pip и сетевой доступ к PyPI. `python -m venv .venv`, `. .venv/bin/activate`, `python -m pip install -e .`. Перед запуском безопасно задайте `BOT_TOKEN` в окружении процесса; при желании `BOT_DB` (по умолчанию `data/bot.sqlite3`). `python -m donation_bot.bot` начинает long polling и подключается к Telegram — не запускайте без разрешения и отдельного тестового бота. Токен не сохраняется в проекте. Боту в группе могут понадобиться права и настройки privacy mode для команд; поведение топиков следует проверить на тестовой группе.

Офлайн-тесты без зависимостей: `python -m unittest discover -s tests -v`; дополнительно проверяется компиляция `python -m compileall -q donation_bot`. В репозитории нет токена и тесты не запускают бота, не подключаются к Telegram и не проводят платежи. Зависимости не зафиксированы lock-файлом; до развёртывания зафиксировать версии, проверить supply chain и выполнить интеграционные тесты Telegram.

## Денежная модель до реализации провайдера
Намерение ≠ счёт ≠ подтверждённый платёж. Целочисленные суммы и ISO-код валюты, без float и без смешивания валют. Для будущего реального подключения нужны: серверное создание заказа с непредсказуемым ID; проверка подлинности уведомлений и/или сверка через API провайдера; строгая проверка суммы, валюты, получателя и статуса; атомарная обработка и уникальность идентификаторов провайдера и операций; отдельный неизменяемый журнал проводок; идемпотентные повторы, reconciliation и обработка возвратов/chargeback корректирующими проводками. Не принимать успех от пользователя, redirect или неподтверждённого webhook. При ошибках fail closed. Финансовые уведомления и рейтинг только по проверенным проводкам с учётом возвратов; согласие пользователя на публикацию проверять при каждом построении рейтинга. Политики видимости, срок хранения, удаление данных, разграничение доступа, резервное копирование, audit, миграции и безопасность ещё не реализованы. Нет обработчика webhook или пути записи подтверждённых платежей — намеренно.

Перед запуском также нужны правовой и налоговый анализ, выбор платёжного провайдера и изучение актуальных правил Telegram (включая ограничения на цифровые товары и Telegram Stars); определить, кому принадлежат деньги и как считать рейтинг по группам/топикам, периоды, анонимность и возвраты. Текущая модель не обеспечивает изоляцию донатов по группам. Не хранить данные банковских карт.

## Выбор основы
Изучены [aiogram](https://github.com/aiogram/aiogram) (MIT, актуальный асинхронный Bot API framework) и [telegram_payment_bot](https://github.com/ebellocchia/telegram_payment_bot) (MIT, работа со списками платежей из таблиц, другой сценарий и user API credentials). Выбран aiogram как готовый транспорт; чужую схему платежей без проверки провайдера не переносим. Документация: [Telegram Bot Payments](https://core.telegram.org/bots/payments), [Telegram Stars](https://core.telegram.org/bots/payments-stars), [aiogram](https://docs.aiogram.dev/). Лицензия зависимостей не является лицензией этого проекта.

## Развёртывание Bandi на VPS

Постоянная рабочая копия: `/home/ubuntu/services/bandi`, ветка `feature/button-interface`.
Python 3.13 `.venv`, aiogram 3.32.0. `BOT_TOKEN`, `BOT_DB` и необязательный `BOT_PROXY` загружаются user-systemd сервисом `bandi-bot.service` из приватного файла `/home/ubuntu/.config/bandi/bot.env` (0600). Не сохранять токен в Git или документации. Снимок установленных версий — `requirements-deployed.txt`.

Раздел пополнения показывает суммы 50–100000 ₽ и произвольный ввод, но не создаёт счёт и не начисляет баланс. Раздел закрепов содержит пример топиков из референса, а раздел тегов — сроки/цены из референса; эти каталоги пока не подключены к группе и не продают услуги. Каждый экран прямо сообщает о недоступности. История показывает только собственные неоплаченные намерения, отдельно от подтверждённых операций. Для данных платёжной модели ничего не изменено.

Управление от пользователя ubuntu: `XDG_RUNTIME_DIR=/run/user/1000 systemctl --user restart bandi-bot.service`. Второй polling не запускать. Сервис не зависит от Buddy, Games World или Threads. Групповой рейтинг отвечает в исходном топике; приватные действия блокируются в группе.
